# @pb/web

The Portfolio Beach web app: React 19, Vite, TanStack Router and Query, Fluent UI v9, AG Grid Community. Phase 0 scope: theme from `config/brand.json`, prototype sign-in with a role switcher, the navigation groups from `docs/06`, the portfolio grid with calculated metrics, the investment one-pager (equity and private credit variants), Data Health, Data Dictionary and the feature-flag admin page. Areas for later phases show a placeholder naming the phase and modules.

```bash
pnpm --filter @pb/web dev        # http://localhost:5173, proxies /api and /health to the API on 3001
pnpm --filter @pb/web test       # formatters, theme, sign-in (jsdom)
pnpm test:e2e                    # Playwright: starts the API over an in-memory seeded database and Vite, runs journey 1
pnpm test:a11y                   # axe-core WCAG 2.1 AA checks on the Phase 0 pages
```

## Rules this app follows
- No hard-coded colors or fonts: `src/app/theme.ts` builds the Fluent theme and the CSS variables from `config/brand.json` (docs/06 section 1). Styles are scoped in `src/styles.css`; tinted panels appear only on the one-pager's deal-details card.
- Numbers and dates follow docs/06 section 3 through `src/lib/format.ts`: $M with one decimal, MOIC with two, IRR with one decimal percent, yields and spreads with two, dates as "Jan 15, 2026" without time zones. Missing values render the single placeholder from `brand.json`; short-period and multiple-root IRRs render "NM".
- The mock credential lives in session storage for the tab only, never local storage (SEC-4.5). Entra ID with MSAL replaces the picker after merge; the role switcher and the banner disappear with it because the API stops reporting `mockIdentity`.
- Every response is parsed with the shared zod contracts; every error is an RFC 9457 problem. A record the user cannot see is a 404 and renders "Investment not found".

## End-to-end tests
`playwright.config.ts` starts `scripts/e2e-api.mjs` (the real API over PGlite seeded with the small synthetic profile, seed 42) and Vite, then runs `e2e/journey1.spec.ts` (critical journey 1: each role sees only permitted records, the walled deal is hidden from a viewer and visible to a wall member, the role switcher changes the acting user) and `e2e/a11y.spec.ts`. In the cloud sandbox the preinstalled Chromium matches Playwright 1.56.1; elsewhere `pnpm exec playwright install chromium` fetches it. Set `PW_CHROMIUM_PATH` to point at an existing browser if downloads are blocked.

## Static preview
`pnpm --filter @pb/web build:preview` builds `dist-preview/` (gitignored): the app in preview mode plus `preview/fixtures.json`, recorded from the real API over the small synthetic profile (seed 42). The router uses the URL hash so deep links work from a static host, and if the recordings cannot be loaded the page says so instead of rendering nothing.

**Recording plan.** `scripts/preview-plan.mjs` lists every request family the pages send through the builders in `src/app/queries.ts`, with their fixed parameters. Ids come from the dataset and the deal-type codes from the seeded taxonomy, so nothing is listed by hand. Every family is recorded for every mock user, so the API's own role guard and row-level security decide between 200, 403 and 404 for each credential (a viewer replays the real 404 for the walled deal). The API audits reads with the wall-clock time, so the audit trail is recorded before any audited read and holds only what the seeded database holds. Bodies are content addressed (each distinct body stored once under a SHA-256 prefix, every key pointing at its hash) and problem request ids are pinned to `preview`. The build log prints the requests and statuses per family, the number of keys, the distinct bodies and the size of `fixtures.json`; the build fails above 8 MB. `src/preview/plan.test.ts` fails when a query builder sends a request the plan does not record.

**Replay.** In preview mode (`VITE_PB_PREVIEW=true`) `src/preview/shim.ts` answers `/api` and `/health` from the recordings. A request the recordings do not cover answers the 404 problem "This request is outside the recorded preview", and its key is added to `window.__pbPreviewMisses`.

**Simulated writes** (`src/preview/routes/`, checked before the recordings): `PATCH /api/v1/flags/{key}`, `POST /api/v1/valuations` (a new Draft), `POST /api/v1/valuations/{id}/commands`, `POST /api/v1/capital-notices/{id}/commands` and `POST /api/v1/preview/reset`. Each one validates the body with its contract's zod schema (400 with paths only, never the values), acts as the credential's recorded `/api/v1/auth/me`, answers 404 for a record that credential's recordings cannot open, evaluates the command with `attempt()` on the docs/18 transition tables and maps a refusal through `WORKFLOW_REFUSALS` in `@pb/contracts` (403 role, 409 command not in the table from this state, 422 failed precondition), honours `Idempotency-Key` and `If-Match` (412 on a stale row version), and answers with `x-pb-simulated: true`. Segregation of duties compares user ids, so a preparer cannot approve their own valuation. There is no wire register in the prototype, so ticket approval is always refused (SEC-12.3 for the ticket's drafter, SEC-12.2 for anyone else). The state lives in memory for the page session, is shared by every role the switcher picks, and is never written to storage; a reload or the reset route forgets it. Reads lay the simulated changes over the recorded bodies (valuation lists, the one-pager's valuation versions, the capital notice list and detail, flags) per credential, so a wall still hides what it hid. Recorded figures stay as recorded: nothing recomputes NAV, MOIC or IRR, and a simulated draft's change ratio stays empty because that ratio belongs to `@pb/calc`, which the preview does not bundle.

**Probe.** `pnpm --filter @pb/web probe:preview` serves `dist-preview` and, in headless Chromium, walks journey 1, visits every route in `src/app/router.tsx` as viewer.one, deal.three, ops.one, head.one, ir.one and audit.one (failing on any recording miss or page error), then runs the simulated journeys at the API level inside the page: a valuation on the position with no quarter-end mark (create, prepare, approve, lock, reopen), the wire-change capital notice, and reset. Checks that need recordings of an endpoint that answered 501 when the preview was built are reported as skipped. It prints one line per check and a summary, and exits non-zero on any failure.

**Safety.** The build checks that the simulation sits only in the dynamically imported shim chunk and that a production build carries none of it, emits no source maps, and finishes by running the employer-data guard over the output (`scripts/check-employer-data.sh --paths`), since git never sees that directory. The preview is a static bundle of synthetic data for review, not a deployment: docs/16 section 5 rules out cloud deployment from the prototype and routes hosted demos through IT, and this repo only adds the build. The bundle reaches no server and holds no credentials; where it may be shared is the owner's call.
