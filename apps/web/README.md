# @pb/web

The Portfolio Beach web app: React 19, Vite, TanStack Router and Query, Fluent UI v9, AG Grid Community, and a small SVG chart kit of its own. Theme from `config/brand.json`, prototype sign-in with a role switcher, the navigation groups from `docs/06`, and the pages listed below; areas for later phases show a placeholder naming the phase and modules.

```bash
pnpm --filter @pb/web dev        # http://localhost:5173, proxies /api and /health to the API on 3001
pnpm --filter @pb/web test       # pages, shared pieces, formatters, preview engine (jsdom)
pnpm test:e2e                    # Playwright: starts the API over an in-memory seeded database and Vite, runs every journey
pnpm test:a11y                   # axe-core WCAG 2.1 AA on every page, at 1280 and 390 pixels wide
```

## Shared pieces
- `components/ui.tsx`: the page vocabulary. `PageHeader`, `Card`, `SectionHeader`, `StatTile`, `NumCell`, `Badge`, `TabNav`, `Toolbar` and `Field`, `EmptyState`, `ErrorState`, `PageSkeleton`, `KeyValueTable`, `SimulatedBadge` and `PhasePage`. `WorkflowSpec` shows a later module's transition table from `packages/workflows` on its phase page, with rules in the code's own words (`lib/workflow-spec.ts`). `TableWrap` is the frame every table sits in: a focusable `role="region"` named after its table, which scrolls sideways inside its card on a phone and keeps visually hidden text from widening the page.
- `components/WorkflowActions.tsx` with `lib/workflow.ts`: the command buttons, the reason dialog, the page's one status line and the action log shared by the valuation board and the capital notice page; the rules for when an action is live and the in-memory action log.
- `components/UnavailableState.tsx` with `lib/unavailable.ts`: what a failed read shows. A 403 or 501 becomes an empty state that says who can see the data or that it is not built yet; anything else is an error. `retryUnlessUnavailable` is the retry policy of the reads that can answer that way.
- `components/PreviewGuide.tsx` with `lib/preview-guide.ts`: in the static preview only, six short walkthroughs (walls, valuation approval, capital controls, the accounting import, analytics and the weekly report, the assistant) naming the mock users by role from the mock user list. A compact card on sign-in; on Home a card the reviewer can hide for the tab, with the preview reset.
- `components/charts/`: the SVG chart kit. `ChartFigure` (title, legend, a table twin behind Show table, tooltips), `HorizontalBars`, `StackedBars`, `LineChart` and `Sparkline`, with `scale.ts` for ticks, compact axis values and category labels: the label column takes about 36 percent of the chart and long labels are cut in the middle so similar names stay apart, with the full name in the tooltip, the aria-label and the table.
- `components/ClientLookThrough.tsx`: each entitled client's share of every vehicle, rendered by Reporting and by the Analytics Clients tab.
- `lib/format.ts`, `lib/dates.ts`, `lib/labels.ts`, `lib/states.ts`: number, date and state display (docs/06 section 3), including `formatMonthYearShort` ("Jun 2025") for chart axes.

## Rules this app follows
- No hard-coded colors or fonts: `src/app/theme.ts` builds the Fluent theme and the CSS variables from `config/brand.json` (docs/06 section 1). Styles are scoped in `src/styles.css`; tinted panels appear only on the one-pager's deal-details card.
- Numbers and dates follow docs/06 section 3 through `src/lib/format.ts`: $M with one decimal, MOIC with two, IRR with one decimal percent, yields and spreads with two, dates as "Jan 15, 2026" without time zones. Missing values render the single placeholder from `brand.json`; short-period and multiple-root IRRs render "NM".
- The mock credential lives in session storage for the tab only, never local storage (SEC-4.5). Entra ID with MSAL replaces the picker after merge; the role switcher and the banner disappear with it because the API stops reporting `mockIdentity`.
- Every response is parsed with the shared zod contracts; every error is an RFC 9457 problem. A record the user cannot see is a 404 and renders "Investment not found".

## End-to-end tests
`playwright.config.ts` starts `scripts/e2e-api.mjs` (the real API over PGlite seeded with the small synthetic profile, seed 42) and Vite, then runs `e2e/journey1.spec.ts` (critical journey 1: each role sees only permitted records, the walled deal is hidden from a viewer and visible to a wall member, the role switcher changes the acting user), `e2e/deal-tabs.spec.ts`, `e2e/vehicles-sponsors.spec.ts` and `e2e/a11y.spec.ts`. The accessibility journey runs axe (WCAG 2.1 AA, zero serious or critical) over every page as operations and over the deal tabs of the walled deal as the approver, at 1280 and at 390 pixels wide, each page once its own content is in. `PB_E2E_API_PORT` and `PB_E2E_WEB_PORT` move the two servers so several checkouts can run side by side. In the cloud sandbox the preinstalled Chromium matches Playwright 1.56.1; elsewhere `pnpm exec playwright install chromium` fetches it. Set `PW_CHROMIUM_PATH` to point at an existing browser if downloads are blocked.

## Static preview
`pnpm --filter @pb/web build:preview` builds `dist-preview/` (gitignored): the app in preview mode plus `preview/fixtures.json`, recorded from the real API over the small synthetic profile (seed 42), `preview/book.json` (the book as the system actor sees it, from `previewBook(dataset)` in `tools/synthetic`: the investment directory with each company's aliases and taxonomy codes, the match guards, the approved quarters, the Locked marks and the invested cost per investment on each bundled extract date, which the simulated intakes check a file against) and the bundled samples under `preview/samples/`: `accounting-{clean,update,defects}.csv` (the three sample exports of docs/14 section 6), `weekly-values-{clean,update,defects}.csv` (the weekly drop folder), `lookthrough-<asOf>.json` and `lookthrough-<asOf>-defects.json` (the look-through folder: the defects extract for the dataset's as-of date, the clean one for the quarter end before it) and `ops-drop-{clean,update,defects,unknown-template}.xlsx` (the ops drop folder). `dist-preview/publish.json` lists every file a publisher maps beside `artifact.html` by path. The router uses the URL hash so deep links work from a static host, and if the recordings or the book cannot be loaded the page says so instead of rendering nothing.

**Recording plan.** `scripts/preview-plan.mjs` lists every request family the pages send through the builders in `src/app/queries.ts`, with their fixed parameters. Ids come from the dataset and the deal-type codes from the seeded taxonomy, so nothing is listed by hand. Every family is recorded for every mock user, so the API's own role guard and row-level security decide between 200, 403 and 404 for each credential (a viewer replays the real 404 for the walled deal). The API audits reads with the wall-clock time, so the audit trail is recorded before any audited read and holds only what the seeded database holds. Bodies are content addressed (each distinct body stored once under a SHA-256 prefix, every key pointing at its hash) and problem request ids are pinned to `preview`. The build log prints the requests and statuses per family, the number of keys, the distinct bodies and the size of `fixtures.json`; the build fails above 8 MB. `src/preview/plan.test.ts` fails when a query builder sends a request the plan does not record.

**Replay.** In preview mode (`VITE_PB_PREVIEW=true`) `src/preview/shim.ts` answers `/api` and `/health` from the recordings. A request the recordings do not cover answers the 404 problem "This request is outside the recorded preview", and its key is added to `window.__pbPreviewMisses`.

**Simulated routes** (`src/preview/routes/`, checked before the recordings): `PATCH /api/v1/flags/{key}`, `POST /api/v1/valuations` (a new Draft), `POST /api/v1/valuations/{id}/commands`, `POST /api/v1/capital-notices/{id}/commands`, the intake routes of every source (the accounting export, the weekly values, the look-through reconcile and the operations workbook drop, with their drop folders and the shared file list), the data exceptions queue and `POST /api/v1/preview/reset`. Each one validates the body and the query with its contract's zod schemas (400 with paths only, never the values), acts as the credential's recorded `/api/v1/auth/me`, answers 404 for a record that credential's recordings cannot open, evaluates the command with `attempt()` on the docs/18 transition tables and maps a refusal through `WORKFLOW_REFUSALS` in `@pb/contracts` (403 role, 409 command not in the table from this state, 422 failed precondition), honours `Idempotency-Key` and `If-Match` (412 on a stale row version), and answers with `x-pb-simulated: true`. Segregation of duties compares user ids, so a preparer cannot approve their own valuation. There is no wire register in the prototype, so ticket approval is always refused (SEC-12.3 for the ticket's drafter, SEC-12.2 for anyone else). The state lives in memory for the page session, is shared by every role the switcher picks, and is never written to storage; a reload or the reset route forgets it. Reads lay the simulated changes over the recorded bodies (valuation lists, the one-pager's valuation versions, the capital notice list and detail, flags) per credential, so a wall still hides what it hid. Recorded figures stay as recorded: nothing recomputes NAV, MOIC or IRR. A simulated draft takes its quarter, its prior Locked mark and its change ratio from `@pb/calc` (`alignedQuarterEnd`, `lockedNear`, `valueChange`), the rules the API uses; the calc library loads only with the shim chunk.

**Simulated intake** (`src/preview/routes/intake.ts`, decision 0009): the bundled samples are the drop folder; an import (a sample by id, fetched as a static asset beside the page, or a CSV uploaded as text) runs the same `@pb/validation` library as the API in the browser: the file is read against `config/accounting_layout.json`, every row is linked, diffed and checked against `preview/book.json` as the system actor (so a walled position links rather than reading as "no match"), with the thresholds of `config/definitions.json` through the one reader the API uses (`intakeSettingsFrom`); the file is keyed by the SHA-256 of its text, so the same text answers the file staged before with `duplicate: true`. A reader sees the rows and the candidates for the positions their own recordings let them open; the rest are counted in `hiddenRows`, never shown. Approve and reject go through the staging transition table (approve by the caller, then promote by the system actor; reject needs a reason and is operations only), act on the rows the caller sees, and are recorded as simulated changes with counts only. The preview's standing rule: promotion changes the staged rows only, never the recorded figures, so the book and every recorded response stay as they were. Intake files exist only in the page session, so the shim answers the intake reads itself and the recording plan does not record them. If `preview/book.json` is missing or malformed, the rest of the preview still loads and only the intake routes answer 503 (the reason is logged as a console warning).

**Simulated weekly values, look-through and workbook drop** (`src/preview/routes/weekly.ts`, `lookthrough.ts`, `opsDrop.ts`): each simulates its API service over the same `@pb/validation` rules and the book. The weekly intake reads the four-column file, links every value, takes its prior (the latest Locked mark of the book on or before the report date, or the weekly value an earlier simulated import promoted after that mark) and runs the weekly rules; approving a value creates a simulated Draft valuation of method weekly_report, which the valuations board and the one-pager show for whoever may see the position. The reconcile reads the bundled extract for the as-of date (a date with none stages a run with no rows and the LT-FILE-01 finding), links, maps the labels through `config/lookthrough_mapping.json` and compares with the book's taxonomy codes, Locked NAV and invested cost; every difference, unmapped label and unresolved link opens a simulated data exception, keyed by the SHA-256 of the date and the rows. The workbook drop decodes the workbook (base64, or a bundled sample), reads it with `@pb/xlsx` in the browser (a `DecompressionStream('deflate-raw')` inflater, the read limits of config), matches it to a template of `config/ops_drop_templates.json` by its sheet names and the SHA-256 of its header cells, maps the header onto the accounting layout and stages it through the one staging the accounting export uses; an unknown template is a refused file with the LAYOUT-05 finding naming the templates. The accounting import and the workbook drop open simulated data exceptions as the API does (unresolved links, fair values that do not tie).

**Simulated exceptions queue** (`src/preview/routes/exceptions.ts`): the exceptions the simulated intakes opened, newest first, with the state, source, severity and (once the contract carries it) file filters and cursor paging. An exception about a staged row linked to a position the credential cannot open is left out and not found on its own, as the row policy hides it in the API; a visible one names its file, row and position. Commands go through `exceptionMachine` (acknowledge takes the exception; resolve and won't fix need a reason; a transition the table lacks is the 409 of `WORKFLOW_REFUSALS`) and `set_ticket` records the ticket without a state change; operations only. Data Health's recorded open exception count is overlaid with the simulated exceptions still open or acknowledged.

**Probe.** `pnpm --filter @pb/web probe:preview` serves `dist-preview` and, in headless Chromium, walks journey 1, visits every route in `src/app/router.tsx` as viewer.one, deal.three, ops.one, head.one, ir.one and audit.one (failing on any recording miss or page error), then runs the simulated journeys at the API level inside the page: a valuation on the position with no quarter-end mark (create, prepare, approve, lock, reopen) and the wire-change capital notice; then the intake journey in the UI (operations stages the defects sample, reads the flagged and exception tiles and the hidden-rows note, approves the validated rows and rejects the flagged ones with a reason; the wall member sees the walled position's row with no note; a viewer is told who intake is for), the weekly values journey (the defects sample staged from the drop folder, the flagged tile and the threshold badge, the approve that creates Draft valuations, found on the valuations board), the look-through journey (the as-of date reconciled, the differences and exceptions tiles, the queue opened from the run, one exception acknowledged, one resolved with a reason, a ticket noted, Data Health counting the open ones), the workbook drop (the clean workbook staged from the drop list with its template named in the banner and approved, the unknown-template workbook refused with the finding naming the templates), the wall member seeing the walled position on each page and a viewer refused on each, and reset, after which every list is empty again. Checks that need recordings of an endpoint that answered 501 when the preview was built are reported as skipped. It prints one line per check and a summary, and exits non-zero on any failure.

**Safety.** The build checks that the simulation sits only in the dynamically imported shim chunk and that a production build carries none of it, emits no source maps, and finishes by running the employer-data guard over the output (`scripts/check-employer-data.sh --paths`), since git never sees that directory. The preview is a static bundle of synthetic data for review, not a deployment: docs/16 section 5 rules out cloud deployment from the prototype and routes hosted demos through IT, and this repo only adds the build. The bundle reaches no server and holds no credentials; where it may be shared is the owner's call. Because the role switcher works without a server, `preview/fixtures.json` holds every mock user's recorded answers: the preview demonstrates row-level security, walls and client entitlements for whichever user is signed in, and does not enforce them against someone who opens that file. That is acceptable only because every figure is synthetic (decision 0008).
