# 06: Brand and UI (prototype uses a neutral Portfolio Beach theme)

The prototype ships with its **own neutral theme**. A deploying firm's brand is applied later as a theme file in configuration. Never hard-code colors or fonts; use tokens from `config/brand.json`.

## 1. Portfolio Beach default theme (placeholder, change freely)
The look is called the ledger look (decision 0026): ink and neutral greys, one cobalt accent, one sans family with tabular figures.

| Token | Value | Use |
|---|---|---|
| `brand.primary` | #1E3A5F | Ink blue: links, primary buttons, the wordmark's mark |
| `brand.accent` | #4C72D9 | Cobalt: focus ring, current tab underline, current step, selected row edge, chart series 1. Never text |
| `brand.sand` | #EEF0F3 | Neutral panel grey (the key keeps its name for the formulas that read it) |
| `ui.bg` | #FFFFFF | Page |
| `ui.text` | #16191D | Text and every figure |
| `ui.muted` | #68707A | Secondary text, on the page background only |
| `ui.border` | #DCE0E5 | Section rules |
| `status.good / watch / bad` | #2E7D32 / #B7791F / #C62828 | Status (meanings fixed) |
| `chartSeries` | #4C72D9, #D9782B, #2A9D8F, #C9A21C, #C05C86, #4E9A3A, #7A5BD0, #D94A3F | Charts, in this order: cobalt first, orange second |

Fonts: **IBM Plex Sans** 400, 500 and 600 for everything (`fonts.ui`, and `fonts.display`, which is the same stack), bundled with the app from IBM's own unmodified files (`apps/web/src/app/fonts/`, SIL Open Font License 1.1), with Segoe UI and the system face behind it; **IBM Plex Mono** 400 (`fonts.mono`, `--pb-font-mono`) only for hashes, wire digits, lock text and a document's page text. No serif. Every digit has the same width, so figures line up in columns; identifiers such as INV-0001 use the sans. Check WCAG AA contrast for all pairs (`apps/web/src/lib/theme.test.ts`).

Type scale (`styles.css :root`, a size and a line height each; the weight is set where it is used): `--pb-text-xs` 11/16 (axis ticks only), `--pb-text-sm` 12/16 (labels, table headers, sub-lines, status words, crumbs), `--pb-text-md` 13/20 (body, cells, navigation, tabs, buttons, inputs), `--pb-text-lg` 14/20 (section titles), `--pb-text-xl` 16/24 (dialog titles), `--pb-text-title` 20/28 (page titles), `--pb-text-fig` 22/28 (key figures; 20/26 under 760px), `--pb-text-prose` 14/22 (commentary and descriptions, at most 72 characters a line). Weights 400, 500 and 600 only. No uppercase lettering and no tracking, except a slight tightening on titles and figures.

Shape and space: radii `--pb-radius-sm` 2px (identifiers, focus outlines), `--pb-radius` 4px (buttons, inputs, notices, menus), `--pb-radius-lg` 6px (dialogs, popovers). Shadows only on what floats over the page: `--pb-shadow-2` (tooltips, menus) and `--pb-shadow-3` (dialogs, the phone drawer). Spacing `--pb-space-1` to `--pb-space-7` (4, 8, 12, 16, 24, 32, 48px); the one value off the scale is a table cell's vertical padding, `--pb-cell-py` 6px, which gives a 32px row.

Derived tokens (`apps/web/src/app/theme.ts`, decision 0007) are formulas over the values above and are the only other colours the web app may use: tints for hover and selection, inks for status text, and the sky and sea colours that nothing paints any more (the sign-in page has no scene and the map is neutral; the formulas stay for the tests that pin them). Colour roles: figures and titles in `--pb-text`; tone is shown only through the ink tokens and dots. Usage rules: `--pb-muted` only on the page background; secondary text on any tinted surface uses `--pb-muted-strong`; the accent is never text (use `--pb-accent-ink` when accent-coloured text is unavoidable); status colours as text only through `--pb-good-ink`, `--pb-watch-ink` and `--pb-bad-ink`, with the raw values kept for dots, borders and fills. Chart series come from `chartSeries` (validated for colour-vision safety) and are never used for text.

## 2. Layout rules
- **Surfaces.** A white page. A section is flat: a hairline rule (`--pb-border`) above it, 16px above its content and 32px below; no frame, no shadow, no tinted panel. The first section after the page header, the tabs, the figures strip or the analytics context row carries no rule, even with an empty result line or a wrapper around the page's body between them. Two columns are two sections side by side, 32px apart, each with its own rule. A frame (1px border, 6px radius, no shadow) is only for what stands apart from the page: dialogs, menus, a form opened in place (`Card panel`). The brand colour is for links, primary buttons and the wordmark; titles and every figure are in the text colour. Always scope styles to a feature folder.
- **Page header.** On a record's page, the trail of where it sits first (a breadcrumb, `PageHeader crumbs`, each earlier step a link); then the title (20/28, weight 600) with the page's actions on the right; then one meta line (13/20, muted) that wraps rather than hides anything. Only a single long plain-text item, such as a file name, may be clipped, with its full text as its title. No rule under the header. When the meta line wraps, no line starts with a dot. Under 760px the actions go under the meta line; under 560px the meta items stack without their dots. Area pages keep their titles: the rail and the tabs already say where the reader is.
- **Section titles.** An h2 in sentence case, 14/20 weight 600 in the text colour, with no underline and no capitals; an optional aside on the right in 12/16 muted, which drops under the title when the two do not fit on one line; commands for the section sit beside the title, never inside the heading (`SectionHeader actions`). A title inside a section is a sub-title, 13/20 weight 600 (`Subhead`). No large decorative headline text.
- **Tables** are the main surface. The header is quiet: no fill, 12/16 weight 600 in `--pb-muted-strong` over a stronger rule (`--pb-border-strong`), and no rules between columns. Rows are 32px: cells 13/20 with 6px above and below (`--pb-cell-py`, the one value off the spacing scale) and 8px at the sides, a hairline between rows and none under the last, contents top-aligned; row headers are weight 500. Figures are right-aligned, of even width and on one line. Links are in the brand colour at weight 500, underlined only on hover or focus. Identifiers (INV-0001, Row 2) are small `--pb-muted-strong` text, never a tag. Totals sit in `tfoot` under the stronger rule, at weight 600. A long table sits in a region of limited height whose header stays in view (`TableWrap tall`), its foot shaded and ruled while rows lie below it; a short table of a few columns (check lists, flags, switches) stops at 880px so a state or a command sits near its words; a table whose rows are being replaced is marked busy and dims (`TableWrap busy`). A selected row takes a tint and the accent along its first cell. A dense table has 28px rows. On paper the header prints in ink over an ink rule and repeats on every page.
- **Tables on phones.** A table wider than the screen scrolls sideways inside its frame, with a soft edge on the side that scrolls and its first column held in view (the position, not the row number, where a table leads with one), the held column's edge ruled only while the table is wider than its frame; its header cell stays over the headers that scroll beneath it, and a second header row scrolls with its columns. Headers may wrap, so a long one never sets its column's width. A key and value table holds one pair a row. Every table stays a table, so screen readers and tests read it the same way at every width.
- **Figures strip.** Key figures sit in one strip between two rules, the cells divided by hairlines (drawn by the cells, so a short last row ends in plain page). Like a table, the strip reaches 8px past its section and its cells keep 8px at their sides, so its labels start on the section title's edge and its rules run as far as a table's. Where labels may wrap, the cells of a row share their rows, so the figures line up without an empty line kept for a label. Label 12/16 weight 500 in sentence case; figure 22/28 weight 600 in the text colour (20/26 on a phone); hint 12/16 muted. A tone is a 6px dot before the label, never on a zero and never the figure's colour. The missing-value placeholder sits on the figure's line at 14px in `--pb-muted-strong`. Two cells across on a phone. A hint names the figure's basis ("Locked marks", "Pooled, XIRR"); how the figure is worked out sits in the cell's title. Home's seven figures sit in one row from about 1100px, four and three below that, two on a phone, with the NAV sparkline (64 by 20) after its hint, so every hint of the strip sits on one line. A strip of two or three figures is compact, its cells as wide as they need; figures that belong apart sit in labelled groups, each its own strip. When a section ends on a strip, the strip's lower rule is the next section's rule. (One exception for now: the base case card's labels keep capitals, because the preview's probe reads them as rendered; `docs/SESSION_LOG.md` lists it.)
- **Status.** A state is a 6px dot and a word (`Badge`), never colour alone and never a pill: the word in the text colour for good and neutral states, in its ink for watch and bad, in `--pb-muted-strong` for a neutral one; the dot in the raw tone (neutral `--pb-border-strong`). A category (a deal type, a source) is plain `--pb-muted-strong` text with no dot. The preview's "Simulated" and an assistant's "AI draft" are a 6px hollow ring and the word, in sentence case (watch ink and accent ink).
- **Check lists.** Checks and their results are one compact table (`CheckList`): Check, Result, Detail and, when any row has one, a command at the end. The result is the page's own word or count ("OK", "Degraded", "3"); a tone only draws a 6px dot before it, and a row with no tone keeps the dot's room, so the results line up. A result that is a sentence runs on across the detail column. An empty detail stays blank. Data health, Home's data health section and the readiness checks use it.
- **Admin and data pages.** Every page of the Admin row (Flags, Audit trail, Access and walls, Integration health, Data health, Data dictionary, Taxonomy, Intake) shows the row. They show descriptions and words: a flag by its description, a readiness check and a dictionary term in words, never a flag key, a check's code or a configuration name. The flags page puts the reason that unlocks the switches above the table, with the switch last in each row (second on a phone, so it stays on screen). The taxonomy is one table with a group of rows for each domain and, from 1100px, an index of the domains beside it.
- **Notices.** A sentence on a quiet band with a 6px dot before it, radius 4px, no border and no bar (`Notice`, or the `pb-notice` classes): the neutral band (`--pb-primary-tint-4`, an accent dot) for what the reader should know, the good, watch or bad tint with its ink when it reports an outcome. The result of the reader's own command sits on the neutral band with a dot in the outcome's colour; a refusal keeps the bad band. A control inside a notice follows the sentence.
- **Empty, error and unavailable states.** One style: a title (13/20, weight 600) and its reason (13/20, `--pb-muted-strong`, at most 72 characters a line), left-aligned, with no frame and no mark; on its own in a section or on the page, a little more room and a 14px title. A page or role that cannot see the data says so the same way, with no icon. An error is a section whose title is in the bad ink after a bad dot. An empty list of actions is one muted line ("No actions yet"); a row with no command leaves its cell blank to the eye and says "No actions" to a screen reader.
- **Loading.** A skeleton in the shape of what replaces it (a title bar, a strip of figures, 32px rows; `PageSkeleton`, `RowsSkeleton` for a list inside a section), marked busy, never a status.
- **Steps** (`StepStrip`). One row of segments across the top of each step's name: done segments dark, the current one the accent, those ahead a hairline. Only the steps done and the current one are named on screen; under 560px the names give way to one line under the row ("Step 5 of 8: IC"), except on a record that sits on no step (a deal that passed), whose strip keeps the names two to a row.
- **Tabs.** Words in a row over a hairline; the current tab in ink at weight 600 with a 2px accent line under it. The first tab's word sits on the page's text edge, its hit area in the gutter. They wrap on a wide screen; on a phone they are one row that scrolls, with the current tab brought to its middle and each end that hides tabs faded, so a tab cut off at either edge shows that more lie beyond it.
- **Portfolio and the deal workspace.** The positions grid reads like a table: the number and the company pinned on the left, then the figures (right-aligned, even width), the state, and the details (vehicle, sponsor, deal type, entry), long names clipped with the whole name in a tooltip, its right edge shaded while columns lie beyond it; its controls are one row over it (search, deal type, active only, then the count, the row density and the export), and Previous and Next show under it only when there is a second page. A position's header carries the trail (Portfolio, then its vehicle), the company with its investment number and its state beside the title, and one meta line; its figures are a step smaller than a page's key figures (20/26); the tab bar stays in view under the top bar while a tab scrolls, its rule darker while it is held there. The Performance tab has a row of links to its sections ("On this tab"), beside the tab bar on a very wide screen and under it otherwise; growth since entry and value creation are one section under the range of the snapshots compared; the quarterly tables group their columns under a header row of their own, each group's first column set off by a hairline. A tab that is not built says so in one empty state, under the workspace's own header. The watchlist is two columns, the position (with its number, vehicle and deal type under it) and its flags (a dot, the flag in words, the message), one column on a phone. A vehicle's figures sit in two labelled groups, capital and returns; the list of vehicles has its chart beside the table from 1200px.
- **Pipeline and sponsors.** The board draws one white column a live stage (Sourced to Closing), divided by rules, each headed by its stage and count over the stronger rule; a stage with no deal says "None". A card has the same rows in the same order on every card (the deal, the company, the sponsor and fund, the deal type, the deal lead, then the target and the days in the stage), each wrapping rather than cut short, so cards compare down a column and nothing on one is lost; the whole card opens the deal. Only a deal past its stage's guide carries a dot (watch, with the guide in its title). Closed and passed deals follow the board as one open table with the same fields. On a phone each stage is a section of its own. How a deal moves between stages is folded under its summary. An opportunity's header carries the trail, the record's facts on its meta line, and on the right the stage as a dot and a word with its days ("IC, 6 days", neutral unless past the guide), the stage commands at full size (the advance named by where it goes, "Advance to Approved", with why it is blocked in words under it) and the preview marker. A deal's stage is a neutral word everywhere else too; the accent marks only the current step, the primary button, focus and the active fit measure. A closing's tie-out is a ledger: commitment, the received total, then the difference under the stronger rule in the outcome's ink, the outcome in words beside the title; a legal term's fields read one a line in words. Once the deal is a position, the closing says so once at its top. A sponsor's directory has its count as the header's meta line and its search as the header's action, the table straight under it; a sponsor's page lists its funds first, and an empty section is one muted line.
- **Documents, extraction, monitoring and the data intakes.** A record's page (a document, an extraction run, a staged file, a reconcile run, an exception) carries its trail (Documents, Documents / Extraction, Intake, Weekly values, Look-through, Exceptions) and its state as a dot and a word at the start of its meta line; the header's actions hold commands only. The preview's "Simulated" marker sits beside the command it qualifies, at the end of its row, not in a section title. In a row a rule's identifier is small monospace words (`pb-rule-id`), several comma-separated, never a pill; a cell's findings say their count once with the dot of the worst severity (or under the validation word, which already says it), the messages folded under it (`pb-details`). An identifier follows the company's name on its line. Figures compare: the extraction value right-aligned, its sign before the dollar sign ("-$7.94M"); what approving a staged row writes as a small grid of the figure, the record's and the file's, both right-aligned, the file's in ink; an unchanged row says "No change" in muted words; the look-through puts a watch dot before the provider figure that disagrees and names the provider's label alone when the taxonomy term reads the same. The extraction review keeps one Source column (the page as a command, then the quote), says once who decided when every decision shares its reviewer and time, and says once why nothing can be decided (approved, failed) instead of a column of disabled buttons. The monitoring board's quarter and as-of day sit over the figures they choose; the report, its due day, the run and the approval are four columns, each status a dot and a word that opens its record. The staging forms keep the browser's own file input, its button drawn as a small secondary button (`pb-file`); the files waiting in the drop folders are one table, each with its folder and its Stage command. An exception leads with what was expected and what was found, side by side. Text columns (a quote, a title, an expected value) keep a width a word fits in, so a phone scrolls the table instead of breaking words; long titles and file names keep one line, cut short with their whole text in the title.
- **Valuations and capital activity.** A valuation version, a capital notice and a wire instruction carry their trail (Valuations / Board, Capital activity / Notices, Capital activity / Wire register); a version's quarter and number follow its company in the title, lighter and in even figures ("Jun 30, 2025 · v1"), and each record's state sits on the title's line. Its commands sit in a flat block directly under the header, with no heading, rule or frame: the command that moves the record on leads as the primary button, a step back (send back, reopen) is a quiet one, why a command is blocked reads under the buttons, and the result line, the last-step sentence and the command notes follow as quiet lines. Then the shared step strip, the figures, and the sections. A notice's hold and alerts are one block of lines (a dot, a word, a sentence), on the page's one bad band when a hold or a bad alert stands; the ticket's release blockers are a dot list with no box. A version's method inputs read as a ledger of pairs, the value on the right. On the board the variance flag is a watch dot in a fixed slot before the change, every action is right-aligned with the step back quiet, the batch bar is a flat row over the table, and on a phone Fair value and Change follow the position. A tab's rule is one quiet line under the tab row (`pb-tab-rule`), not a notice and not the meta line. The suggestions list comes first; the chosen suggestion is a section under it, its header holding the company, its state, the quarter and source, and its commands on the right. Commitments fold to their figures: the sponsor, vintage and strategy under the fund's name, the client under the vehicle, the over-called word on the figure's line, the API's total in the table's foot. Long registers (notices, trade tickets, wire instructions) sit in a tall region whose header stays in view. An empty section says so in one muted line (`EmptyLine`): what is missing, then why.
- **Reporting.** The weekly report, Clients and Disclosures keep their title and tabs while they load or cannot be shown. The weekly report's meta is three items with a dot between them (period, as of, prepared for); a vehicle's type is the second line of its name; the total row is the report's own, in the table's foot; a mover's direction is a small drawn mark and Up, Down or Flat in the quiet ink, never a status colour (a fall in value is reported, not alarmed); an overdue notice says how far past due under its date, in the bad ink; what output is not built yet is said once with the footnotes and never printed. A client's section says why its totals are missing once, on a line under its strip, which each missing total points to; the vehicle row that causes it carries the reason on its placeholders. A package's page carries its trail (Reporting / Packages), its state first in the meta line and the commands of its gate in the header, with why a blocked one is blocked under it; its sections run one under the other. In the positions of a package a missing figure carries a small letter after its placeholder, and the reasons are listed once under the table by letter (each cell keeps its reason in its title and for a screen reader); the quarter end's own mark reads quiet, so a roll-forward stands out. The passed checks sit behind a quiet toggle on the table's last rule. The list of packages leads with where each stands and what its checks said, then what it is; the version is a figure. A reader who may not start a package reads why beside the button. The start form is a framed panel opened in place, Cancel before Start at its right.
- **Charts** (`components/charts`). A chart's title is 13/20 weight 600 with what it is drawn from on the line under it (12/16 muted); a chart that is all its section holds has its title as the section's heading, at a section title's size, and one whose section title already names it keeps its title only for screen readers and its table (`hideCaption`). The legend (two series or more) and "Show table" sit on the right of the title, and on a phone under it, the legend at the text edge and the command at the right; "Show table" and "Show chart" are a quiet text command with a 16px table or chart icon, the ring only for the keyboard. Gridlines are hairlines, the zero line `--pb-border-strong`, tick figures 11px tabular in muted, category labels 12px in the text colour. An axis's figures share one unit and as many decimals as the step between them needs, so no two read alike. Bars are 12px with square ends in 26px rows beside their labels; under 480px of chart width each label sits whole on its own line above its bar (40px rows) unless every label of the chart fits beside its bar whole (years, say), and only labels set beside their bars are cut, never on a phone. A bar's value sits past its tip; in a stacked bar of several segments each value that fits stays inside its segment on a plate of the page colour, the segments parted by a 1px rule, and a stacked bar of one segment prints its value past its tip. Lines are 1.75px with no wash under them; one series has no end label (its title names it), two to four have end labels that move apart rather than drop, each joined to its line by a short leader when moved; an axis may be broken after a point that is not to scale (two short strokes across the foot, the line running on); an axis that need not start at zero is framed by its figures. Charts set side by side to be compared share one value axis (`SharedScale`). A scatter may hold a mark far beyond the rest at the axis edge as a hollow ring with an arrow and its figure printed, with a line under the chart saying so; the tooltip and the table keep every exact figure. A scatter that is its section's main figure is 360px tall from 900px of width. The tooltip has a 2px radius and a hairline border, and shows the missing-value placeholder for a missing figure.
- **Analytics.** Each tab says what its figures are over once, in a row directly under the tabs (`PageContext`): the as-of date and the scope as short items with a dot between them, the tab's own controls on the right (Exposure's Group by, Value creation's Export CSV with its result beside it), and a scope sentence on a line of its own when it adds something. No section repeats the tab's name or the date, and a section that holds one chart takes the chart's title. The page title and the tab row sit close, one header with the tab row's rule as its only line. Exposure groups by one choice of six (Sector to Vintage) from a laptop up, a list on a phone. The value creation filters are an even grid of six small fields with the count and Clear filters on their bottom line (three across under 1320px; on a phone one Filters button that says how many are set, the fields two across under it). The value creation table groups its columns under a header row of their own (EV / EBITDA, Net debt / EBITDA, Growth since entry, Gain by driver), centred over a rule as wide as the group, each lower header short on screen ("Entry", "Current") with its whole name for a screen reader, each group's first column set off by a hairline from top to foot; the number and the company stay in view while the figures scroll (the number alone on a phone); one sort mark turns when the order flips. How the value creation split is made is one line under the bridge, the method folded under "How the split works". A credit position's title is the company after its number in quiet figures, its terms one pair a row on a phone, its latest figures a strip under the terms with the covenant and payment states one line under it, and its amortization schedule a short table under a sub-title.
- **Fields and controls.** A field's label sits above its control, 12/16 weight 500 in `--pb-muted-strong`, in sentence case. Filters over a table carry no rule of their own. Forms lay their fields in a row that wraps (`pb-form-row`) or an even grid (`pb-form-grid`). A command among text is a quiet button (`pb-btn-quiet`: link-coloured words, a tint under the pointer); one choice of a few is a segmented control (`pb-segmented`, the chosen one tinted). A page with one group of commands may lead with one primary command and say why a command is blocked, under the button it explains, from that button's edge. On a touch screen or a phone every control is at least 44px tall; in a table a button keeps its drawn size and an invisible band 44px tall takes the touch, and a row's commands stay on one line, so the row stays as tall as its text.
- **Dialogs.** A frame of 6px radius with the dialog shadow, a 16/24 title, over the page dimmed with the text colour at 32%. The page keeps the scrollbar's room, so opening a dialog moves nothing.
- **Shell.** A navigation rail the full height of every page (224px, `--pb-surface-2` with a rule on its right) holds the wordmark at its top and the navigation, and stays in view while the page scrolls. A white top bar (44px, a hairline under it) spans the page's column only: on the left the prototype marker (a watch dot, "Prototype" and the data rule, cut short when the bar is narrow and whole in its title), on the right the user (initials, the name, the switcher showing the role in words with the users grouped by role, and Sign out). Navigation items are 30px, 13/20 weight 500 with 16px icons in `--pb-muted-strong`; the current one is white in a hairline ring at weight 600, with no accent bar; group labels are 12/16 weight 500 in sentence case. The first thing the keyboard reaches is "Skip to content", which moves focus to the page.
- **Shell on a phone** (under 760px). One 48px bar: the menu, the mark, the prototype marker as its dot and "Prototype" (the whole sentence stays inside it for a screen reader), the user's name and Sign out. The navigation opens in a drawer from the start edge that writes the data rule out, holds the same groups and the user switcher, and closes when a link is followed. At any width there is one main navigation and one status element.
- **Wordmark.** A 16px square in the brand ink (2px radius) holding three bars of falling length in the page colour, read as an allocation, then "Portfolio Beach" at 14/20 weight 600 with no tracking.
- **Sign-in.** One column at the page's gutter, at most 640px wide, under a bar like the app's (the wordmark, and the synthetic data sentence on the right or, on a phone, under it): the title "Sign in" and its sentence, the users in one framed list grouped by role (a grey row naming the role, then a 36px row a user with the name, the role in words and a chevron), the Entra note, and the preview's walkthroughs folded. No split screen, no brand panel, no scene.
- Navigation groups: Home, Pipeline, Portfolio, Sponsors, Documents, Valuations, Capital activity, Reporting, Analytics, Assistants, Admin. Every label is in sentence case (Data health, Data dictionary).
- Each role sees its own areas first (decision 0021, `config/role_focus.json`): the navigation leads with the role's group under the role's name, then "More" and "Data"; tabs inside an area follow the role's order; the home page leads with "Your work" and then the sections that role uses. Nothing is hidden: a link the role's list leaves out keeps its usual place. Focus never hides a tab; access does: a tab is left out only for a role that cannot read what it lists, as the Suggestions tab of the Valuations area is for the roles that do not read valuation suggestions (decision 0023).
- Deal workspace tabs: Overview (one-pager), Performance, Sponsor & Contacts, Diligence, Closing, Valuations, Documents, Tasks, Activity. Reporting Period selector shared across tabs.
- One-pager sections: header banner (company, vehicle, as-of period, investment date), Business Description, Investment Summary at Entry, Deal Details (CV fields shown only for CV deals), Thesis, Sourcing Angle, stat tiles (Invested Capital, Current NAV, Gross MOIC, Gross IRR), Financial Performance table (At Entry, Prior Year, LTM / Current, YoY), Business Highlights, Deal Status.
- Private credit one-pager: the Deal Details section becomes Credit Terms (facility, seniority, coupon split cash / PIK, floor and spread, OID, maturity, call protection, covenants); stat tiles are Funded, Par, Fair Value, Current Yield and Gross IRR; the performance table adds Interest Coverage, Leverage Through Tranche, LTV and Covenant Status. Equity-only fields (EV / EBITDA multiples) are hidden.
- Every AI-generated text shows an "AI draft" badge until approved.

## 3. Number and date display
- $M with one decimal in tables; multiples 1 decimal + "x"; MOIC 2 decimals; IRR 1 decimal %; yields and spreads 2 decimals % (spreads may also show in basis points); coverage ratios 1 decimal + "x"; LTV 1 decimal %.
- Dollars to the cent ("$12,450,950.25") only where two figures are compared with each other and a rounded million would hide the difference between them: what a report check expected and what it found (decision 0024). Worked from the digits of the decimal string, never through a float.
- Missing or not meaningful: a single `MISSING` constant (a hyphen or "NM"); never 0, Infinity or -100%.
- Prior Year means the same fiscal quarter one year earlier only.
- Dates: "Jan 15, 2026"; investment dates "January 2026"; UTC-safe formatter.

## 4. Generated documents
Template-driven (pptx, docx, xlsx) with stable chart sizes and positions between periods; change logs stored outside the output; disclosures inserted from a disclosure library.

## 5. Motion, and the co-investment map
- Motion is decoration: nothing a reader needs is said only by an animation, and nothing moves under the reduced motion setting (`prefers-reduced-motion`, or a slow display). Every animated or transitioned selector is repeated, exactly as it is declared, in a reduced motion block at the foot of its own stylesheet, where it is switched off (a media block adds no specificity, so a shorter selector would lose): the app's in `styles.css` ("Motion policy", which also stops Fluent's spinner), the map's at the foot of `pages/analytics/map/map.css`, the charts' at the foot of `components/charts/charts.css`, the pipeline pages' at the foot of `pages/pipeline/pipeline.css`, the extraction run's at the foot of `pages/extraction/extraction.css`, the valuation suggestions' at the foot of `pages/valuations/valuations.css`, the client packages' at the foot of `pages/reporting/packages/packages.css`, the analytics tabs' sort mark at the foot of `pages/analytics/analytics.css`, and each other stylesheet that animates at its own foot. `apps/web/src/components/motion.test.ts` reads every stylesheet of the web app and fails on a selector left moving.
- Durations and easing come from the tokens in `styles.css :root`, mirrored for script in `apps/web/src/components/motion.ts` (`MOTION`, `EASE`, `useReducedMotion()`), which a test holds to the stylesheet: `--pb-dur-instant` 80ms (a press, a tooltip), `--pb-dur-fast` 120ms (colour, border, a chevron, every exit), `--pb-dur` 180ms (small entrances, a status line), `--pb-dur-enter` 220ms (a page, section or dialog arriving), `--pb-dur-slow` 320ms (a bar growing, a step filling, the radar opening), `--pb-dur-draw` 480ms (a line drawing), `--pb-stagger` 24ms between siblings, `--pb-rise` 4px of travel; `--pb-ease` (decelerate, entrances and hovers), `--pb-ease-inout` (lines drawing, camera moves), `--pb-ease-exit` (exits only). Nothing overshoots.
- What moves: each new block of a page rises 4px into place once, a step behind the one before; the figures strip arrives cell by cell; the sparkline of Home's NAV draws in once and its latest point follows; a chart's marks arrive once its canvas has its real width (a line draws along its length and its end marker and label fade in after it, bars and segments grow from their baseline in turn, a bridge's steps grow in order, a scatter's reference line fades in and its points arrive after it, printed values fade in after their bar), never again while the chart stays on the page, so "Show table", a filter or a sort replays nothing, and the view the reader swaps to (the chart or its table) fades in; a chart's tooltip fades in at once; the current tab's underline draws in when it becomes current; a step strip's segments done fill in order, and after a command only the segment that changed; a disclosure's triangle turns while its content appears at once; links, tabs and quiet buttons change colour, never position; the result of the reader's own command drops in beside the button and the row it changed washes once; a table whose rows are being replaced dims while it is busy; the deal workspace's tab bar darkens its rule when it comes to rest under the top bar; the pipeline board's columns arrive left to right, once, and a closing checklist or diligence row the reader changed washes once; the fit meter's bars fill as their points land on the radar; a valuation, change request or wire register row the reader's command changed or added washes once; the chosen valuation suggestion rises into place under the list once per choice; a package's start form drops in under the header when the reader opens it, the chevron of a package's passed checks turns and the rows it shows fade in; an extraction value the reader decided washes once, the quote it cites fades in on the drawn page, a page the reader picks (the drawn page of a run, the text of a document) fades in where the old one was, and a pick from a value's source brings its quote into view inside the page's frame (smoothly, the one smooth scroll, never under the reduced motion setting); loading appears only if it lasts and pulses until replaced, the app's only loop; the sign-in column settles and its users arrive in turn, once; the phone's navigation drawer slides 16px in from its edge and fades, and leaves faster; the co-investment map opens once in about a second (the coast draws, the land and then the borders fade in, the markers pop into place in turn, with no overshoot), a marker that comes into view as the map comes closer grows in, a chosen or focused marker's ring spreads once and is gone, and the map's flights take a line's drawing time (a zoom step the slow time, a keyboard pan the base time); a sortable column's mark fades in on the column that takes the order and turns when the order flips. What never moves: a figure being read (no count-up), table rows on a refresh, sort or filter, anything per keystroke, the navigation, titles and the tab row, focus rings. An entrance plays once, and nothing keeps moving but a loading pulse.
- The co-investment map (decision 0017) is neutral (decision 0026): the page's white for water, `--pb-border` for land, country borders in the page colour, a thin coast in `--pb-border-strong`, no grid of lines, no gradient and no frame but a hairline above and below. Markers take the chart series by deal type; a marker holding more than one type takes the brand primary; a chosen or focused marker is ringed in the text colour, one under the pointer (or whose row is) in the stronger rule. Its controls are flat: the deal types two ticked squares in their marker colours, the status one choice of three, the regions joined over the map's top left corner with Play tour after them, and zoom in, zoom out and the whole world one column of buttons with hairlines between them. The panel beside it has no frame, only a hairline as tall as the map; in the table under it a row's place is a small locate button. On a phone the map is 4:3, opens on the cities, and shows the panel only once a marker is chosen. No other colour is introduced.
- The radar chart (decision 0018) takes the first chart series. Its web fades in (`--pb-dur`), its shape grows into place from a little under its full size (`--pb-dur-slow`, after 80ms) and its points land in turn (`--pb-dur-fast` each, `--pb-stagger` apart, from 240ms), once; each measure's bar beside it fills (`--pb-dur-slow`) as its point lands. A label beside a spoke starts at least 14px across from the spoke's end, so it never touches a score of 100 there. A measure with no score is a dashed spoke with the missing-value placeholder and a gap in the shape, never a point at the centre. The score is printed at every label.
- A map is never the only way to the information: the same positions are in a table under it, and positions it cannot place are listed with the reason.
- The website (`apps/site`) speaks the same language (decision 0026): the app's motion tokens, name for name and value for value; a block rises 8px into place over 240ms the first time it enters the view, blocks that arrive together 40ms apart, once; links, buttons, screenshots and the tour's links change colour, never position; nothing loops and nothing scrolls by itself. Its reduced motion block (reduced motion or a slow display) repeats each moving selector exactly, at the foot of `apps/site/src/styles/site.css`, and `apps/site/src/site.test.ts` holds both rules. Its look follows the app: one sans, ink headings at weight 600, sentence case labels with no tracking, flat bands of page white and panel grey meeting at a hairline (one dark band for the controls), a 1px frame around each screenshot, 4px and 6px corners, a full radius only on a dot, and the product's mark beside its name and as the tab icon.

## 6. Words on the page
The owner asked on 2026-11-12 that the product not "come across as AI generated". What gave it away was mostly its wording, so these are rules:
- **A page never cites the build guide.** No document path ("docs/18 section 4"), control number ("SEC-12.3"), module or phase number ("M8", "Phase 4"), configuration key or file path in anything a person reads. Those belong in comments, test names, documents and pull requests. `apps/web/src/lib/copy-guard.test.ts` reads the page source and fails on one.
- **The API keeps its citations.** A refusal from the API still names the control behind the rule, for the audit trail and the engineer, and tests pin that. The page removes the reference when it shows the sentence (`lib/references.ts`).
- **Say a thing once.** A subtitle does not repeat the tabs under it or a notice beside it. A page title needs a subtitle only when the subtitle tells the reader something the title does not: the as-of date, whose view it is.
- **Not built is "Not built yet".** A planned page says what it will hold. Which phase of the build brings it is the roadmap's business.
- **Quiet beside content.** An empty state is a title and its reason, with no frame and no mark, wherever it sits. A row with no command says nothing on screen; "None" in an actions column is noise.
- **A badge is for a state that matters.** A step that is simply still ahead gets no badge (the stage strip names only the current step and the ones done). On the pipeline board a deal's type is a line of text, and only an aging deal carries a badge.
- **The work comes first.** Home opens on the portfolio's figures and what needs attention. The preview's walkthroughs sit after it.
