# @pb/workflows

Typed transition tables for every state machine in `docs/18_WORKFLOWS_AND_STATE_MACHINES.md`: valuation, staging records, capital notice and funding, deal stage, reporting package, document classification, extraction run, deal change request, data exception, wire instruction, closing, underwritten base case and valuation suggestion.

- `attempt(machine, from, command, ctx)` is pure. It returns the next state or a typed refusal (`forbidden`, `role`, `precondition`). The API persists the state, writes `audit.event` and emits the outbox event; tests call the same function.
- `forbiddenPairs(machine)` enumerates every (state, command) pair the table does not list, and the test suite rejects each one even for an actor holding every role.
- Preconditions encode segregation of duties (preparer never approves; `notAmong` keeps the source reviewers of a suggested mark from both approvals of its valuation), required reasons, the IC gate with an audited Approver override, the closing checklist and allocation tie-out, and the wire controls on trade tickets.
- `requireReason` is used as the precondition itself where a reason is all a transition needs (send back, reopen, reject, resolve, wont_fix), so the web's `commandOptions` can tell the page to ask for one.

- `controls-capital.ts` and `controls-closing.ts` hold the control rules that are arithmetic rather than transitions, as pure functions (plain data in, plain data out, the date passed in): business days, the wire change hold window, the notice alerts and the release blockers of a trade ticket; the allocation tie-out on received amounts, the closing gates, the diligence gate with what was carried over a reopen, and the IC decision round. The API and the static preview call the same functions, so the two cannot answer differently.
- `controls-suggestion.ts` holds the rules of the valuation suggestions (`docs/18` section 14), over the figures `@pb/calc` works out (`docs/08` section 12): the settings read from `config/definitions.json` and refused by name when one is missing (`suggestionSettings`), when no suggestion applies to a position and quarter (`suggestionBar`), the mark a suggestion is set against (`referenceOnHand`), which source on hand gives the suggestion and what the others say beside it (`readSources`, `selectSuggestion`), what a reader is shown with a stored suggestion (`suggestionReading`), what an approval or a refresh does to the suggestions of a quarter (`derivationStep`, `sameSuggestion`), the record the suggestion machine reads (`suggestionCommandRecord`), the keys a draft valuation carries once a suggestion is on it (`suggestionDraftKeys`, `withSuggestionKeys`, `keepSuggestionKeys`) and who is barred from approving that valuation (`sourceReviewersOf`).

Changing a workflow means changing the table and `docs/18` together; the generated tests fail on any transition that one has and the other lacks.
